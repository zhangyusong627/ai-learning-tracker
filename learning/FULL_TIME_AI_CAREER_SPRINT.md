# 全职 AI 转型与求职冲刺计划

## 1. 目标与时间边界

- 执行周期：2026-07-27 ～ 2026-09-15。
- 8 月 12 日启动首批投递，不等两个项目全部完成后再启动市场验证。
- 9 月中旬前完成主要面试流程并争取确定 Offer。
- 求职定位：以 Java 工程经验为根基的 AI 大模型应用工程师，而不是放弃 Java 后从零竞争纯算法岗位。

## 2. 三条并行主线

| 主线 | 最终证据 | 优先级 |
|---|---|---|
| 学习 | RAG、结构化输出、Tool Calling、LangGraph、评估与安全闸门的可解释掌握证据 | 高 |
| 作品集 | 两个独立 GitHub 项目，均可运行、可验证、可讲解 | 最高 |
| 求职 | Java + AI 题库、模拟面试记录、投递漏斗和真实面试反馈 | 高 |

学习不再按技术名词横向铺开。每个新知识点必须回答：它解决作品集中的哪个业务问题，产出什么可验证证据。

## 4. 作品集定义

### 作品集一：金融机构接入 Skill

解决的问题：金融机构的 PDF、Word、Excel 等接入资料格式不一，人工梳理字段、流程和差异成本高且容易遗漏。

输入与输出：

```text
公开或自造机构文档
→ 统一解析与证据定位
→ 标准领域模型和字段映射
→ 差异清单、风险与待确认项
→ 人工确认
→ 配置及 Java 接入骨架
→ 编译、契约测试和评估报告
```

V1 验收线：

- 至少支持三种文档格式和两个自造机构样例；
- 输出符合 JSON Schema 的标准模型、字段映射和差异报告；
- 关键结论可追溯到文档证据，低置信度内容进入待确认队列；
- 人工确认后才能生成配置或 Java 骨架；
- 生成结果通过确定性校验，至少包含编译或契约测试；
- README、架构图、演示脚本、评估数据和已知边界完整。

### 作品集二：AI 智能守护

解决的问题：不同机构、产品和接口的容量、超时、并发特征不同，靠人工持续调整规则成本高、响应慢，也缺少统一审计链路。

输入与输出：

```text
模拟运行指标 + 历史事件 + 治理知识库
→ 专家规则基线
→ Agent 生成策略建议与依据
→ 硬性安全边界校验
→ 人工审批
→ 模拟执行、观测、回滚和审计
```

V1 只做模拟控制面，不连接任何真实生产系统。模型只负责建议，确定性规则负责限制最大调整幅度、冷却时间、回滚条件和审批要求。

周一至周五按 7 小时基准排程，低于 7 小时时先砍扩展阅读，不砍核心实践和复盘：

| 时间 | 内容 |
|---|---|
| 3 小时 | 当周作品集的核心实现 |
| 1.5 小时 | 为实现服务的新知识学习与最小实践 |
| 1.5 小时 | Java / AI 面试准备，必须包含口述或手写 |
| 0.5 小时 | 复习 Day +1 / +7 / +30 |
| 0.5 小时 | 测试、提交证据和当日复盘 |

周六、周日每天至少 4 小时：

- 2.5 小时端到端集成、评估或修复 Bad Case；
- 1 小时项目讲解、模拟面试或简历投递；
- 0.5 小时周复盘和下周裁剪。

## 8. 投递与面试节奏

- 8 月 9 日前：确定目标岗位描述样本，整理一版 Java + AI 简历和 60 秒自我介绍。
- 8 月 10～11 日：完成首批岗位匹配和简历定稿。
- 8 月 12 日：启动首批投递，不把“两个作品集全部完成”作为前置条件。
- 8 月 12～16 日：每周 5～8 个高匹配岗位，使用反馈校正简历和项目讲法。
- 8 月 17 日起：根据回复率和面试反馈调整关键词、项目讲法与题库，每周 8～12 个有效岗位，不追求无差别海投。
- 每次面试后 24 小时内记录：问题、回答缺口、正确模型、补强任务、是否需要改简历或项目证据。
- 9 月 1 日起优先保障真实面试、复试和定向补缺，停止无直接求职价值的新技术扩展。

## 9. Java 与 AI 面试范围

Java 主线不暂停：

- Java 集合、并发、JVM、异常与 I/O；
- Spring / Spring Boot、事务、MySQL、Redis、MQ；
- 高并发、限流、熔断、动态线程池、可观测性；
- 资金网关类系统的机构接入、差异化适配、稳定性和领域治理设计。

AI 主线围绕作品集：

- Prompt、Structured Output、Embedding、Chunk、RAG 检索与评估；
- Tool Calling、Agent 与 Workflow 的区别、LangGraph 状态和人工确认；
- 幻觉、Prompt Injection、数据边界、确定性安全闸门；
- 为什么生成代码后仍需要编译、契约测试、评估集和审计。

## 10. 每日完成证据

一天不能仅凭“代码跑通”标记完成，至少要留下：

1. 一个学习者独立完成的核心判断、伪代码或关键实现；
2. 一个可复现的运行、测试或评估结果；
3. 一个失败案例及修正结论；
4. 一段 3～5 分钟的项目口述或面试回答记录；
5. 下一次复习日期，或来自真实投递/面试的反馈项。

## 11. 范围控制

出现进度风险时按以下顺序裁剪：

1. 取消无作品集用途的通用 Demo；
2. 取消低优先级 UI 美化和复杂部署；
3. 减少框架横向比较，只保留项目实际采用的方案；
4. 降低功能数量，但不取消评估、安全边界、测试、README 和演示；
5. 不能通过压缩 Java 面试准备来换项目进度。
