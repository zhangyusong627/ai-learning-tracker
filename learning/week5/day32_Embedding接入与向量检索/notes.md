## 二、向量记录结构

```text
id + document + embedding + metadata
```

- `id`：稳定且唯一的 Chunk 标识，支持更新、删除和幂等重试；
- `document`：可供 LLM 阅读、引用和溯源的 Chunk 原文；
- `embedding`：Chunk 的语义向量；
- `metadata`：来源、版本、状态、部门、权限和结构信息；
- `distance`：查询时临时计算的距离，不是固定存储字段。

Chroma 中 `documents` 是 Chunk 文本列表，不是 LangChain `Document` 对象。映射关系：

```text
LangChain Document.page_content → Chroma documents
LangChain Document.metadata     → Chroma metadatas
```

## 三、统一语义坐标系

文档索引和问题检索必须绑定一致的：

- 模型名称与版本；
- 向量维度；
- 查询指令；
- 归一化配置；
- 相似度算法；
- 索引版本。

维度一样不等于语义坐标系一样。同维度的不同模型混用可能不报技术异常，但会造成召回率和查准率大幅下降。

## 四、相似度指标的工程含义

- Cosine：主要比较方向；Chroma cosine distance 越小越相关；
- L2：比较两个向量端点的空间距离，不只是比较长度；
- Inner Product：同时受方向和长度影响；
- 向量归一化：把向量长度调整为 1，维度和方向不变。

工程决策：优先遵循模型官方建议，在标注评测集上验证，不凭单条查询决定指标和阈值。

## 五、metadata 过滤与检索顺序

学习者完成的普通员工过滤条件：

```python
EMPLOYEE_FILTER = {
    "$and": [
        {"version": {"$eq": "V2"}},
        {"status": {"$eq": "published"}},
        {"allowed_role": {"$eq": "employee"}},
    ]
}
```

权限过滤应作用于向量检索空间，不能先全库 TopK 再做权限过滤。否则 TopK 可能被未授权文档占满，使排名稍后但有权限的正确证据无法进入候选。

## 六、数据生命周期与索引升级

- `add`：新增确定不存在的记录；
- `upsert`：存在则更新，不存在则新增，适合幂等重试；
- `query`：按问题向量和 metadata 条件检索；
- `delete`：删除指定记录。

索引状态：

```text
building → validating → active → retired
                ↓
              failed
```

模型升级使用新索引完整重算，经过评测、灰度和原子切换后上线，并保留旧索引的回滚能力。

如果新文档在旧索引仍对外服务时必须立即上线：

```text
旧模型 → index-v1 → 立即查询
新模型 → index-v2 → 为后续切换准备
```

## 七、批量 Embedding 质量闸门

入库前必须检查：

- 输入 Chunk 数量与输出向量数量一致；
- 每个向量的维度与索引配置一致；
- 不包含 `NaN`、正无穷和负无穷；
- Chunk ID、正文、向量和 metadata 一一对应；
- 文本没有发生未记录的静默截断。

正确检查点顺序：

```text
生成向量
→ 入库前校验
→ upsert
→ 入库后验证
→ 更新检查点 success
```

程序崩溃后，从最后一个确认成功的检查点恢复。对状态不明的失败批次使用稳定 ID 和 `upsert` 重放，不从第一批全部重做，也不直接跳过失败批次。

## 八、本地模型与远程 API

- 本地模型：数据不离开内部环境，但需自行承担 GPU、部署、扩容和监控；
- 远程 API：上线快、运维少，但需处理数据合规、网络、限流、超时和调用成本。

身份证号、薪资和绩效等敏感文档，在没有完成脱敏、供应商安全评审和数据合规评估前，优先本地模型。本地部署仍需权限、加密、网络隔离和日志脱敏。

## 九、异常分类

| 异常 | 类型 | 处理 |
|---|---|---|
| `429 Too Many Requests` | 临时可重试 | 有限次数、指数退避、随机抖动 |
| 网络超时 | 临时可重试 | 设置单次超时、总时间和最大次数 |
| 输入超过 Token 上限 | 确定性数据错误 | 二次切分，不原样反复重试 |
| 输出数量不一致 | 质量错误 | 整批阻止入库，拆小批次定位 |
| 向量维度不一致 | 配置漂移 | 阻止入库，查明模型路由和索引配置 |
| 静默截断 | 语义完整性错误 | 禁止无记录截断，按结构二次切分 |

## 十一、学习者费曼解释

> 文档和问题必须使用同一个 Embedding 模型，否则不在同一个语义坐标系中，正确结果无法被召回。

> 批量处理失败后应从已确认成功的检查点恢复，不用从头重做，也不能跳过失败批次。

> 权限过滤应在 TopK 之前限制检索空间，否则未授权文档可能占满 TopK，使有权限的正确答案被排除。

## 十二、误区与修正

| 原始想法或问题 | 修正后模型 |
|---|---|
| 曾把 Embedding 放在 Chunk 之前 | 标准流程是先切 Chunk，再对每个 Chunk Embedding |
| 将 Chroma `documents` 理解为 LangChain `Document` | Chroma `documents` 是 Chunk 字符串列表 |
| 把 L2 理解为只比较向量长度 | L2 比较端点距离，受所有维度差异影响 |
| 把向量非法值称为非法字符 | 应检查 `NaN` 和 `Infinity` 等非法数值 |
| 索引迁移场景只写入 index-v1 | 立即上线时要同步写入 index-v1 和 index-v2，分别使用绑定模型 |
