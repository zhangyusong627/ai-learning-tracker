## 核心模型

### 离线索引

```text
文档 → 解析 → Chunk → Embedding → 向量数据库
```

入库记录需要同时保留：

- `vector`：语义相似度计算；
- `content`：交给 LLM 的原始证据；
- `metadata`：来源追踪、权限过滤和引用展示。

### 在线问答

```text
用户问题
→ 问题 Embedding
→ 检索相关 Chunk
→ 可选 Rerank
→ 组装 Prompt
→ LLM 生成
→ 返回答案和来源
```

## 费曼解释

### 为什么每个问题都要重新检索

不同问题的语义目标不同，需要选择不同的证据 Chunk。知识更新只是重新检索带来的附加价值，不是最主要原因。

### 为什么不能只保存向量

向量只负责检索，原始 `content` 才是 LLM 能阅读、用户能验证的证据；`metadata` 用于追溯来源。

## 故障定位原则

先检查检索结果中是否已经存在正确证据：

- 没有正确证据：检查解析、切分、Embedding 和检索；
- 已有正确证据：检查 Prompt、上下文组织和模型生成。

## 当前持续误区

- 已修正：每次重新检索的主要原因不是知识可能更新，而是问题改变后相关证据也会改变。
- 已修正：检索测试数据不能只有原始文档和 metadata，还必须包含测试问题及预期证据映射。
- 待加强：阅读陌生 Python/LangChain 代码时，需要先逐行确认对象、输入和输出，再进行根因诊断。

## 最小实践

文件：`practice/minimal_rag.py`

预测结果：问题“员工一年可以休多少天年假？”应首先召回“员工每年享有 10 天带薪年假”，依据是两者语义目标一致。

### 运行证据

```text
已索引 Chunk 数量：3
Top 1：员工每年享有10天带薪年假。distance=0.2485
Top 2：员工每周可以申请两天远程办公。distance=0.3575
最终回答：根据提供的资料，员工每年享有10天带薪年假。[1]
```

学习者正确解释：`top_k=2` 会按 distance 从小到大强制返回两条候选，Top K 只代表排名，不保证每条结果都达到相关性要求。

## 工程化扩展

- 无有效证据时应拒绝回答，不能把低相关 Chunk 强行交给 LLM；
- `chromadb.Client()` 的内存数据会随进程退出而丢失，生产环境需要持久化索引；
- 权限过滤必须发生在 Chunk 进入 LLM 之前；
- 文档版本和索引版本必须可追踪，避免更新失败后继续引用过期知识；
- 相关性阈值需要基于真实问题集评估，不能直接照抄固定数值。

### 完整生产架构

1. **离线索引层**：原始文件存储 → 解析与清洗 → 文本切分 → Embedding → 向量数据库；同时维护文档版本、索引版本和解析质量。
2. **在线问答层**：API 网关 → 身份认证 → 问题路由 → 问题 Embedding → 权限过滤 → Top K 检索 → 阈值过滤/可选 Rerank → Prompt 组装 → LLM 生成 → 输出与引用校验。
3. **治理与安全层**：权限规则、metadata、版本管理、间接 Prompt 注入防御、敏感信息过滤和引用追溯。
4. **运维与评估层**：运行日志、链路耗时、错误告警、召回评估、回答忠实度、引用正确率和 Bad Case 分析。

### 五类生产异常边界

- **输入文档**：解析结果为空时阻止入库并记录异常，不能把空内容当作成功数据。
- **索引构建**：新版本索引未完整构建时继续使用完整旧版本，不能混用不完整的新旧索引；完成后原子切换。
- **在线检索**：权限服务不可用时采用 fail closed，拒绝检索，不能降级为查询全部文档。
- **生成阶段**：检索文档中的文字只作为参考数据，不能执行其中“忽略系统要求”等间接注入指令。
- **输出阶段**：引用必须存在于本次检索证据中，并能映射到正确的文件、版本和页码；不存在或映射错误时拦截并重试或拒绝。

## 三层测试

### 1. 概念理解：通过

问题：正确证据未被召回时，为什么只优化 Prompt 无法从根本解决？

回答证据：LLM 没有获得正确答案的原始信息，只能依赖不可靠的预训练记忆或编造，无法给出有依据的回答。

### 2. 代码诊断：补讲后通过

- 第一题使用不同 Embedding 模型且运行前提不严谨，题目不计分；
- 学习者在补讲后准确解释：离线与在线必须使用同一 Embedding 模型，确保处于同一语义坐标系；
- 新题中独立发现 `documents` 与 `metadatas` 的位置映射错误，会导致正文正确但来源错误。

### 3. 场景迁移：通过

面对“只要求固定商务语气和三段式格式”的需求，学习者判断不应使用 RAG，因为没有外部知识、更新和引用需求，应优先使用 System Prompt、Structured Output 和输出校验。

## 独立决策任务

制造企业技术支持助手方案：

- 1 万份动态设备手册：使用 RAG，理由是私有知识、更新频繁、需要引用和权限控制；
- 实时设备状态：使用 Function Calling 调用设备 API，不能依赖可能过期的向量索引；
- 主要风险：文档更新但索引失败时，用户会看到基于旧版手册的过期答案和引用；
- 检索测试数据：测试问题 + 预期 Chunk + 来源 + 页码 + 文档版本。

集团内部制度问答迁移任务：学习者独立给出了离线索引、在线问答、治理安全、运维评估四层架构，并正确安排身份认证、权限过滤、阈值过滤、输出校验、版本管理、日志告警和召回评估。
