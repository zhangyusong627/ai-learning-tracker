## 当前理论模型

- Chunk 过大会混合多个主题，造成语义稀释和上下文噪音；
- Chunk 过小会把条件和结论拆开，造成语义割裂；
- overlap 用于降低语义恰好跨越切分边界的风险，但过大会增加重复和成本；
- 有明确标题和条款时优先结构化切分，超长章节再使用递归字符切分；
- Top K 控制候选数量，threshold 控制最低相关质量；
- similarity 通常越大越相关，distance 通常越小越相关，过滤方向不能混淆。

## 一、Chunk 优化的核心原则

理想的 Chunk 是：

> 能够完整表达一个业务事实，同时不过度混入其他主题的最小语义单元。

### Chunk 过大

- 多个主题混在一起，造成语义稀释；
- distance 可能变大；
- 检索结果包含无关内容；
- Prompt 噪音和 Token 成本增加。

### Chunk 过小

- 条件、结论和操作步骤可能被拆开；
- 回答完整问题时必须同时召回多个 Chunk；
- Top K、阈值或排序稍有变化就可能丢失部分证据。

### 推荐切分顺序

```text
文档结构优先
→ 章节、条款、FAQ、操作步骤
→ 超长语义块二次切分
→ 段落、句子、标点
→ 字符长度兜底
```

- `chunk_size`：控制目标长度或最大长度，不负责确定真正的语义边界；
- `chunk_overlap`：降低切分边界语义割裂的风险，但不能保证语义完整；
- 子 Chunk 必须继承来源、章节、版本和索引等 metadata。

## 二、Top K 与相关性阈值

### Top K

从向量数据库中返回最相近的 K 个候选。即使知识库没有答案，Top K 通常仍会返回相对最接近的内容。

### Threshold

对候选证据执行最低相关质量准入：

```text
Top K 候选
→ 阈值过滤
→ 有可靠证据：进入后续链路
→ 无可靠证据：拒绝回答并记录
```

- distance 越小越相关：`distance <= max_distance`；
- similarity 越大越相关：`similarity >= min_similarity`；
- 两种指标的过滤方向不能混淆。

阈值过宽松可能引入噪音；阈值过严格可能过滤正确证据，产生漏召回或假阴性。

## 三、Recall、Precision 与无答案拒答率

- **Recall（召回率）**：应该找到的正确证据中，实际找到了多少；
- **Precision（查准率）**：返回的证据中，有多少确实相关；
- **无答案拒答率**：知识库没有答案时，系统是否正确拒绝回答。

```text
阈值宽松：召回率可能提高，查准率可能下降
阈值严格：查准率可能提高，召回率可能下降
```

高风险系统可采用两道门：候选召回阶段相对宽松，最终证据准入阶段相对严格。如果只有一道阈值且结果会直接进入 LLM，则安全规程、合同等高风险场景应优先保证证据可靠性。

## 四、标注评测集

标注评测集是提前写明预期结果的测试问题集合。`Ground Truth` 可以理解为标准证据或标准事实。

```python
{
    "question": "超过5000元的报销由谁审批？",
    "answerable": True,
    "expected_section": "报销制度",
    "expected_facts": ["部门负责人审批"],
    "expected_source": "员工制度V2.pdf",
}
```

无答案问题示例：

```python
{
    "question": "公司是否提供住房补贴？",
    "answerable": False,
    "expected_section": None,
    "expected_facts": [],
}
```

生产评测集应覆盖：

- 有答案和无答案问题；
- 同一问题的不同表达；
- 模糊问题、错别字和跨段问题；
- 与知识库主题相似但实际无答案的问题；
- 不同用户角色、文档权限和文档版本；
- 预期来源、章节、关键事实和禁止出现的错误事实。

标注评测集不是训练数据，而是类似 Java 自动化测试中的“输入、预期结果、实际结果和断言”。

## 五、生产级权限、版本和质量校验

权限需要分层处理：

1. **请求级身份认证**：确认用户是谁，Token 无效时在入口直接拒绝；
2. **检索级文档授权**：根据用户部门、角色和密级，通过 metadata 过滤用户无权访问的 Chunk；
3. **Prompt 前最终复核**：再次校验权限、文档版本、发布状态、解析质量和来源有效性。

更准确的生产链路：

```text
用户问题
→ API 网关
→ 身份认证
→ 加载权限上下文
→ 问题 Embedding
→ 权限、版本、发布状态过滤 + Top K 检索
→ 相关性阈值过滤
→ Rerank
→ Prompt 前权限、版本和质量复核
→ Prompt 组装
→ LLM 生成
→ 输出安全校验
```

原则：未授权内容不应该被检索出来，更不能进入 LLM 上下文。

## 六、API 网关

API Gateway 中文叫 API 网关，是外部请求进入后端系统的统一入口，类似公司大楼的前台和门禁。

常见职责：

- 根据路径把请求路由到具体服务；
- 验证 Token，确认请求身份；
- 限流，避免恶意调用和模型费用失控；
- 生成 request_id，支持完整链路排查；
- 处理 HTTPS、IP 策略、请求大小和基础安全规则；
- 在多个服务实例之间负载均衡。

Java 常见实现包括 Spring Cloud Gateway、Nginx 和 Kong。

API 网关不能替代 RAG 服务中的文档级业务授权：

```text
API 网关：你是谁，请求应该转发到哪里
RAG 服务：你可以检索哪些具体文档和 Chunk
```

## 七、学习者费曼解释

- Chunk 太大会引入噪音并降低检索精度，太小会导致语义割裂；
- 有明确文档结构时优先按章节切分，超长章节再二次递归切分；
- overlap 通过把上一个 Chunk 的尾部保留到下一个 Chunk，降低边界语义割裂风险；
- Top K 负责查询最相似的候选，阈值负责证据准入；
- 无证据通过阈值时，在线链路拒答，离线链路检查知识、切分、Embedding 和阈值；
- 生产阈值必须经过足够评测问题验证，不能根据少量样本以偏概全。

## 八、错误、误区与修正

| 原认识或不完整表达 | 正确模型 |
|---|---|
| tiny 的 distance 最低，所以一定最好 | 单句检索效果好不代表跨句、流程类问题效果好 |
| 阈值过滤后“答案不完整” | 如果正确证据全部被过滤，是漏召回或假阴性，系统通常会拒答 |
| 没有结果通过阈值等于数据库没有返回 | 数据库可能返回 Top K，但没有候选达到证据准入标准 |
| 高风险系统统一使用严格或宽松阈值 | 候选召回可相对宽松，最终证据准入应严格 |
| 权限只需在 Top K 后检查 | 入口认证、检索级授权和 Prompt 前复核需要共同存在 |
| overlap 可以保证语义完整 | overlap 只能降低边界割裂风险，不能替代结构化切分 |
