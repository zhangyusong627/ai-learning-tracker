# Day 28：LoRA 微调实战（暂缓）

## 状态

⏭️ 暂缓，不计为已学习或已掌握。

## 决策日期

2026年7月14日

## 暂缓原因

当前阶段的核心目标是构建可用的 AI 应用。相比立即训练模型，继续学习 RAG、检索评估、工具调用、Agent 和工程化交付，更符合当前目标，投入产出比也更高。

Day 25 已经完成微调和 LoRA 的概念入门，足以支持现阶段进行技术选型。现在直接开展 LoRA 实操会引入训练数据、算力、评估、部署和模型版本维护等额外复杂度，但尚无明确业务问题需要通过微调解决。

## 当前保留的认知

- 微调用于改变模型的稳定行为或领域能力，不是给模型临时补充事实知识；
- 动态、可追溯的领域知识通常优先考虑 RAG；
- 输出格式和行为约束通常先尝试 Prompt、Structured Output 和工具调用；
- LoRA 是参数高效微调方法，但“成本更低”不等于“当前有必要使用”。

## 重新进入条件

只有同时具备较明确的业务理由和评估条件时，再恢复本课程：

1. Prompt、RAG 和工具调用已经验证过，仍无法达到目标；
2. 已积累合法、干净、有代表性的领域训练数据；
3. 已建立基线模型、独立评估集和量化验收指标；
4. 能承担训练算力、部署、监控和模型版本维护成本。

## 恢复后应完成的内容

- 准备并检查训练、验证和测试数据；
- 选择基础模型与 LoRA target modules；
- 配置 `rank`、`alpha`、`dropout` 等参数；
- 运行训练并保存 Adapter；
- 与基线模型进行独立评估；
- 分析过拟合、灾难性遗忘、数据污染和部署成本。

## 决策结论

跳过本节实操是技术优先级调整，不代表 LoRA 没有价值。后续由真实问题触发学习，而不是为了完成课表而训练模型。
