## 第 7 天延迟复习证据

### 已确认

- 离线和在线必须使用相同的 Embedding（向量化）模型、版本、配置和维度；
- 权限和版本 metadata（元数据）过滤应发生在 Top K（相关度最高的前 K 条结果）之前；
- `retrieved_candidates（检索候选结果）` 不能直接进入 Prompt（提示词），必须经过相关性阈值形成 `accepted_evidence（通过门禁的最终证据）`；
- LLM（大语言模型）输出需要经历 `raw_output（原始输出） → final_output（最终输出）` 校验；
- 高风险机构规范缺失关键字段表时，必须阻止入库。
- 原始输入正确但输出引用非法时，重试必须携带失败原因和合法引用编号；
- 引用编号存在只代表结构校验通过，不代表结论一定受到证据支持；
- 原子结论不一定能独立返回，完整报价等强依赖结论需要按组处理。

### 本轮修正

- 离线链路补回了 `解析 → Chunk（文档切片） → Embedding（向量化）` 中缺失的文档切片阶段；
- `require_complete（业务是否要求完整解析）` 表示业务完整性要求，不是“当前是否已经完成”；
- 一个 `Document（解析文档）` 可以产生多个 `Chunk（文档切片）`，不能要求两者数量相等；
- 必须保持 `Chunk（文档切片）、Chunk ID（文档切片唯一标识）、metadata（元数据）、Vector（向量）` 一一对应；
- Embedding（向量化模型）只返回少量无身份向量时，不能部分写入，否则可能发生静默错配。
- 文档版本必须同时参与 Chunk ID（文档切片唯一标识）生成并写入 metadata（元数据）：前者避免主键碰撞，后者支持版本过滤；
- 过滤后置主要破坏目标数据集上的召回率和 Top K（相关度最高的前 K 条结果）完整性，不宜笼统称为“召回正确性”；
- 金额、利率等确定性校验应先做数值和单位归一化，而不是泛化为语义相似度；
- 复合回答应拆成可校验的原子结论，同时保留结论组和依赖关系。

## 学习者独立决策

金融机构还款接口规范采用整批校验后批量写入：

```
所有 Chunk（文档切片）成功
→ ID（唯一标识）、metadata（元数据）、Vector（向量）数量与位置校验通过
→ 执行一次批量写入

任何一项失败
→ 整批拒绝
→ 记录原因
→ 修复或重试
```

核心理由：部分写入可能造成正文、向量和 metadata（元数据）错误映射，也会形成不完整索引版本。

2. 高风险文档 `partial（部分成功） + require_complete=True（真，业务要求完整解析）`：在 Embedding（向量化）和写入前拒绝；

4. 同位置、同正文的 `v1（版本一）/v2（版本二）` 生成不同的 Chunk ID（文档切片唯一标识）；
5. 同一集合共存 `v1（版本一）/v2（版本二）` 共 14 条记录，查询版本二时只召回版本二；
6. 第一次输出引用不存在的 `[E3]` 被拦截；
7. 第二次输入加入失败原因和合法编号白名单后，输出修正为 `[E1]`；
8. 最终状态：`answered_after_retry（纠错重试后回答成功）`。

## 三层评估

### 第一层：识别与解释

通过证据：

- 闭卷重建离线索引和在线问答主链路；
- 解释解析部分成功、OCR（光学字符识别）介入和业务完整性门禁；
- 经修正后准确区分 Document（解析文档）、Chunk（文档切片）、Vector（向量）的数量关系；
- 准确指出过滤后置影响的是召回率和目标范围内的 Top K（相关度最高的前 K 条结果）完整性。

### 第二层：应用与诊断

通过证据：

- 判断无身份的 11/12 Vector（向量）不能部分入库；
- 选择高风险金融规范整批校验、原子写入；
- 区分输入组装错误与大模型输出幻觉；
- 判断非法引用不能只删除编号，应删除完整无效结论并重新校验；
- 设计“确定性规则优先、小模型辅助、低置信度转人工”的事实校验路线。

### 第三层：迁移与独立决策

通过证据：

- 判断未完整构建的 `v2（版本二）` 不得对外检索；
- 提出灰度、原子切换、保留 `v1（版本一）` 回滚版本；
- 补充后的完整发布顺序：

```
v2（版本二）在不可检索构建区写入
→ 全量数量、身份、质量和业务完整性校验
→ 标记为可发布
→ 按租户或流量灰度
→ 原子切换活动版本指针
→ 观察运行和业务指标
→ 保留 v1（版本一）回滚窗口
→ 确认稳定后下线 v1（版本一）
```
