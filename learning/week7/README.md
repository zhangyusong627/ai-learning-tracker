## 8.5 学习证据

- [Day 45：RAG 量化评测与 Bad Case（失败用例）分析](day45_RAG量化评测与BadCase分析/notes.md)
- 作品集提交：`322d415 feat: add RAG retrieval quality evaluation`
- 优化结果：多粒度表格切块 + BM25 查询扩展 + 查询意图排序 + RRF 将 Hit@5/Recall@5 从 50% 提升到 100%；衡丰 API 文档改为 PDF 并重建索引后，MRR 为 0.7389；阈值后召回率为 91.67%，无答案拒答率为 100%，90% 自动化质量闸门通过。
- 当前边界：15 条黄金集参与过调试，不能描述为生产准确率；Precision@5 仍为 25%。项目已收敛为 Chroma 单链路，下一步是独立保留集和 OCR。

## 通过标准

- 每个关键映射均有证据或明确标为待确认；
- 机构、产品、版本和权限条件在 Top-K 检索前生效；
- 未批准映射禁止生成 Java；
- 每个生成方法绑定 Evidence、Mapping、稳定 chunk ID 和文档定位，并通过追溯校验；
- Java 生成物通过编译和契约测试；
- 不能用模型“看起来合理”的回答代替黄金集评估。
